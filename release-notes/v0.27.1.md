# phonton-cli v0.27.1 — Hosted goals no longer wait for the index

0.27.1 cuts what Phonton itself costs in CPU and memory around a goal. It
changes no model settings and no command. Every number below was measured on
one 16-thread Windows laptop on 13 November, with 0.27.0 and the new build
run back to back.

## The semantic index is built in the background

With a cloud key, 0.27.0 built the whole semantic index before a goal's
first model call, on every goal, and kept nothing on disk. Its 120-second
limit could not stop a slow build, because the build never yielded to the
timer, so a large repository held a goal back for as long as its index took.

The index is now built on a background thread. A goal's first lookup waits
up to 10 seconds for it. Until the index is ready, the goal runs without
indexed context. Ending the goal stops the build after the batch in flight.

On a generated repository of 6,000 functions, the same goal took 29 seconds
the first time and 13 seconds after that, instead of 52 seconds every time.

## Each signature is embedded once

Symbol vectors are kept on disk, one file per repository under `vectors/` in
the embedding cache. The files hold vectors, not source text.
`phonton index watch` fills the same cache.

Indexing this repository (106 source files, 3,278 signatures) a second time
took 4 CPU-seconds instead of 1,360.

A first index is cheaper too. Signatures are embedded one per model run,
with the runs spread over the cores, instead of in padded batches of 32. The
vectors are the same. A first index of this repository took 347 CPU-seconds
and 405 MB instead of 1,360 CPU-seconds and 803 MB.

## Local goals start four fewer processes on Windows

The CPU name is read from the registry instead of through a PowerShell
process. A local goal starts 29 processes instead of 33 and finished in 13.7
seconds instead of 17.5 on the same fixture. `phonton models status` took
0.2 seconds instead of 2.0.

## Verified

- Four tests were added: a signature is embedded once and reused by later
  builds, a stopped build keeps the vectors it made, lookups do not wait for
  a failed or slow build, and the CPU name read from the registry is trimmed.
- `cargo fmt`, `cargo clippy` with `-D warnings` and the workspace tests pass
  in CI on Linux and Windows. On macOS, CI runs clippy for the CLI and the
  local runtime's tests. The release build passes.
- Three small goals against the live Anthropic API on the generated
  repository (one on 0.27.0, two on the new build) ended review-ready with
  the fixture's test passing. One of them ended while the index was still
  being built.

## Still limited

- The numbers come from one Windows machine. Nothing was measured on macOS
  or Linux.
- A first index still uses every core while it runs, and the embedding model
  holds about 330 MB for the length of a goal that uses the index.
- The first index on a machine still downloads the embedding model (87 MB),
  now on the background thread.
- Local goals (`phonton goal --local`) do not use the semantic index, so only
  the Windows start-up change affects them.

## Install

```text
npm install -g phonton-cli
```

Or download a binary from GitHub Releases, or
`cargo install --git https://github.com/phonton-dev/phonton-cli phonton-cli --locked`.
