# phonton-cli v0.26.0 — Cloud goals run your own checks

With a cloud key, 0.25.2 picked its own checks: Cargo, a package's
`npm test`, or the browser check. A Python repository stopped at
"Verification not run", and standard and frontier work went to larger models
than the configured one. 0.26.0 lets a cloud goal run the test commands you
give it and stay on one model, and it gives Claude 5.5 models room to think.

## Cloud goals take `--check`

`phonton goal --check '<JSON array>'` now works without `--local`, parsed
the same way as `phonton goal --local --check`:

```text
phonton goal "fix the parser" --check '["python","-m","pytest","-q"]' --yes --allow-host-checks
```

Each check runs on the verification copy in place of the detected Cargo,
`npm test` and browser checks, and must exit 0. Repeat the flag for several.
The worker and Phonton's independent re-verification both run them. Without
the flag, detection is unchanged.

## One model on every tier

`pin_model = true` under `[provider]` in `~/.phonton/config.toml` sends every
tier to the configured `model` instead of escalating to larger models, for
example to compare models fairly. It is off by default.

## Claude 5.5 prices in receipts

Receipts price Claude Haiku 5.5, Sonnet 5.5 and Opus 5.5 at list prices for
prompts up to 100K tokens instead of reporting `pricing_known: false`.

## Claude 5.x goals have room to think

With an Anthropic key, a hard goal on Claude Haiku 5.5, Sonnet 5.5 or
Opus 5.5 could end at once with
`anthropic response has no text block (stop_reason: max_tokens)`. These
models think by default, thinking counts toward the reply cap, and Phonton
sent 8,192 tokens. In a 51-exercise Aider Polyglot run on Claude Haiku 5.5,
this ended 2 of Phonton's 8 failures (Rust `forth` and `bowling`).

Claude 5 and later models now get 64,000 tokens, and every Anthropic reply
streams, so a long one is not dropped as an idle connection. A reply that
still stops before any text is asked once more at low effort, and both
attempts count in the receipt. Older Claude models keep 8,192.

## Verification fixes

- A `node_modules` that is a symlink or a Windows junction now reaches the
  verification copy. It was dropped, so tests could not find `jest`.
- A test command the shell cannot find (`'jest' is not recognized`,
  `command not found`) stops as verification unavailable instead of failing,
  retrying and escalating to a larger model. This covers `npm test` and
  `--check` commands.

## Verified

- Regression tests cover checks that replace detection and run in the
  verification copy, `--check` reaching worker verification, a missing test
  runner on Windows and POSIX shells, a linked `node_modules`, the model pin
  on every tier, Claude 5.5 prices, and a thinking-only reply that stops at
  `max_tokens` and is retried at low effort.
- Against the live API, `claude-haiku-4-5` and `claude-haiku-5-5` answered
  through the streamed path with text and token counts.
- On the release binary, the Rust exercises `forth` and `bowling`, which hit
  the 8,192-token cap before, ended review-ready on Claude Haiku 5.5 with
  their tests passing.
- A Claude Haiku 5.5 smoke with `--check` and `pin_model = true` on three
  Aider Polyglot exercises (Python `scale-generator`, JavaScript `ledger`,
  Rust `luhn-from`): each goal ended review-ready on Haiku 5.5 without
  escalating, with its tests passing and its cost priced. On 0.25.1 the
  Python goal stopped at "Verification not run", and the JavaScript goal
  escalated to Sonnet 5.5 after `jest` went missing from the verification
  copy.
- `cargo fmt`, `cargo clippy` with `-D warnings`, the workspace tests in CI,
  the release build, `phonton doctor`, and `phonton doctor --provider`
  against Anthropic all pass.

## Still limited

- Without `--check`, a cloud goal still detects only Cargo checks and tests,
  a package's `npm test` script, and the browser check. For other stacks,
  Python included, pass your test command with `--check`. Without one, the
  goal stops with "Verification not run" instead of applying an unchecked
  change.
- A cloud `--check` counts as passing whenever it exits 0, even if it ran no
  tests, so give a command that fails when it finds none.

## Install

```text
npm install -g phonton-cli
```

Or download a binary from GitHub Releases, or
`cargo install --git https://github.com/phonton-dev/phonton-cli phonton-cli --locked`.
