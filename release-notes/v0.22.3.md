# phonton-cli v0.22.3 — Honest receipts

## No more invented savings

Every 0.22.2 TUI goal opened with `0 tok  saved 100%  vs Σ 35000  best 100%`,
and runs on local or unpriced models kept showing "saved N% vs naive" with a
"NEW BEST" flash. The baseline was a fixed 35,000 tokens per subtask, not a
measurement. That line is gone:

- Priced models show the estimated cost and the estimated saving against
  frontier pricing, as before.
- Unpriced and local models show the token count only. A hosted model with
  no listed price used to show reference-tier figures as its own cost and
  saving, in the TUI and in `phonton review`.
- `phonton plan` prints `tokens: ~3500 estimated` without the baseline
  (`--json` still carries it).

## Readable output

Found by driving the real TUI and CLI through a first goal on a fresh
repository:

- `plan`, `goal`, `review`, `why-tokens` and the TUI receipt name a subtask
  by its headline ("Implement method `remove`") instead of repeating the
  whole goal after it.
- The TUI receipt no longer repeats "no run command" (it is listed under
  known gaps), no longer labels ordinary runs `execution: provider`, and
  says "history only" for checkpoints.
- Costs print with four decimals everywhere, so the receipt and the cost line
  agree ($0.0008, not $0.001 next to $0.0008).
- The stage track keeps the elapsed time on its own line in an 80-column run
  pane.
- The no-tests note in `phonton plan` says the project's own tests still run
  on every edit, and that "with tests" in the goal plans a test subtask.

## Release pipeline

The npm workflow now waits up to 5 minutes for the registry before reporting
failure; 0.22.2 published correctly but its 60-second check timed out.

## Install

```bash
npm install -g phonton-cli
phonton doctor
```
