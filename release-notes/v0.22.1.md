# phonton-cli v0.22.1 — Diffs that land

## Fewer wasted retries

Models often miscount the `@@ -start,count` ranges in a unified diff even when
every line they quote is right. Phonton used to reject those hunks, send the
error back, and pay for another attempt. Now it recomputes the counts from the
hunk body and, when the stated line is wrong, moves the hunk to where its
unchanged and removed lines match the current file. A hunk that matches
nowhere still fails verification.

Measured with DeepSeek flash (`deepseek-flash`), Windows 11, release builds:

- Direct prompts with Phonton's worker format, 13 non-empty diffs: 6 applied
  as sent, 13 after recounting and relocating.
- New `ledger` smoke suite (four edits inside a 339-line module, 3 runs each,
  hidden acceptance tests):

| Build | Accepted | Tokens | Cost | Wall time |
| --- | ---: | ---: | ---: | ---: |
| 0.22.0 | 12/12 | 218,139 | $0.172 | 533 s |
| 0.22.1 | 12/12 | 108,591 | $0.063 | 238 s |

Small n, one model, one machine; token use varies run to run. Reproduce with
`node benchmarks/smoke/run.mjs --arm cloud --runs 3 --tasks ledger-thousands,ledger-parens,ledger-balance-on,ledger-csv-quote`.

## Local models in one command

```bash
phonton models catalog                  # models that fit this machine
phonton models setup qwen2.5-coder:3b   # runtime, download, calibrate, select
```

`setup MODEL` stops at the first step that fails, for example when the machine
is too short on free memory to calibrate. Plain `phonton models setup` still
installs only the runtime and now prints the next step. Download progress no
longer prints `? / ? bytes` for stages without a size.
