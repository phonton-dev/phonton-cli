# phonton-cli v0.22.0 — Product Hunt beta

## Fewer wasted tokens, better first-try diffs

- Workers get the exact current source of the files they edit (bounded), so
  diff context lines match instead of being guessed from signatures.
- Later subtasks in a goal see a one-line note per finished subtask instead of
  a replay of every earlier prompt and diff.
- The system prompt and duplicate retrieval slices are no longer sent twice.

These are mechanism changes. We have not published a before/after token
measurement for this release; `phonton why-tokens` shows provider-reported usage
for your own runs.

## TUI

- Pitch-first welcome with the ADE loop, what every goal gets, and starter goals.
- Width-adaptive footer, unclipped help overlay, empty-state Goals panel.
- Esc/Ctrl+C need a second press to quit.

## Commands

- `phonton why-tokens`: per-subtask provider usage for the latest goal.
- `phonton proof export --latest --format json`: typed proof bundle.

## Local models (preview)

Source builds include the local model manager (`phonton models …`) and the
bounded local runner (`phonton goal --local …`). See `docs/local-harness.md`.

## Beta continuation fixes

- Python cache directories are excluded from local source snapshots, so a
  baseline check can regenerate bytecode without being mistaken for a source
  edit. Source-change and runner-shadow protections remain active.
- Explicit per-goal scope/model/check approval in the calibrated local TUI route.
  Host execution remains a separate permission; Apply remains a separate action.
- Complete reported token totals including strategy proposals, honest unknown
  runtime provenance and durable, serialized run-record updates.
