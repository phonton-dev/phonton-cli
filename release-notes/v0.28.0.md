# phonton-cli v0.28.0 — Local models that reason get room to think

0.28.0 changes how a local goal runs on a model that reasons before it
answers, such as `qwen3.5:4b`. Calibration can now keep the model's own
thinking mode, and the goal loop leaves each model call room for the
reasoning and the edit. Hosted goals get two fixes, for large files and for
projects written as ES modules.

## Recalibrate after upgrading

A profile saved by 0.27.1 or earlier keeps `think:false`, so nothing in the
loop below changes for it until the model is measured again:

```text
phonton models calibrate MODEL
```

## Calibration measures the thinking mode

On a machine that generates 20 tokens per second or more, calibration also
measures the model's own thinking mode and keeps it when its edit and
new-file probes pass. Before, it kept `think:false` whenever that worked.
Probes in that mode may generate a quarter of the context (512 to 2,048
tokens), so reasoning does not use up the limit before the answer. Slower
machines keep `think:false`. Calibrating a model that reasons takes longer,
because its probes reason too.

## The local loop on a model that reasons

- A goal with one editable path and no explicit budget reserves one
  calibrated response of output for each of its 4 model calls, up to 16,384
  tokens, instead of 4,096 tokens in all. The smaller reserve cut the later
  calls to 512 tokens, which the reasoning used up.
- Each call is charged the output tokens the runtime reports, not its whole
  limit, so short replies no longer shrink the calls after them.
- When the scope is one existing file of at most 100 lines and the model
  uses search/replace, the first edit and every repair ask for the whole
  corrected file, so a file that needs several changes no longer takes one
  call per change.
- The restart strategy call sends `think:false` when the `think:false`
  probes passed. Its reasoning used up the strategy's 192-token limit in 14
  of 14 calls across four laptop runs, and each of those goals stopped with
  its other calls unused. A strategy that is cut off or unusable no longer
  ends the goal: the restart edit runs without it.
- A restart whose strategy points at a line inside a small symbol is bound
  to that symbol's edit choice instead of ending with "Strategy source anchor
  was omitted from the edit choices".

For every local model, a repair prompt now carries up to 4,000 characters of
the failed checks' output instead of 450.

## Hosted goals

- The semantic index reads `.mjs`, `.cjs`, `.mts` and `.cts` files. A
  project written as ES modules had none of its own source in the index.
- A file a worker asks for with `NEED_FILES` is sent whole while the files
  it asked for total 160 KB or less, instead of as excerpts once it passed
  48 KB. A worker may ask for files three times in a subtask, and a granted
  request no longer uses up one of its attempts at the diff.
- With `PHONTON_LOG=debug`, each worker reply is logged with its prompt size
  and the token counts the provider reported.

## Measured

On one Windows laptop with 16 GB of RAM and a 6 GB GPU, `qwen3.5:4b`, the
same 20 Exercism Python exercises, scored by the exercises' own tests:

| Build | Tests passed | Claimed | False claims | Median time |
| --- | ---: | ---: | ---: | ---: |
| 0.27.1 settings, thinking off (nine runs, 2026-11-10) | 8 to 10 | 7 to 9 | 0 | |
| This release | 14 | 13 | 0 | 41 s |

The builds on the way here passed 12, 16 and 11 of the same 20. All of
those differences came from the first three model calls, which got the same
limits in every build, so one run of 20 cannot separate 11 from 16. What
held in every run is that no goal claimed a pass its tests did not confirm.

On a model that does not reason (`qwen2.5-coder:3b`, the 36 goals of the CI
smoke run), the builds accepted 13 to 15 goals, against 14 before.

## Verified

- New tests cover short replies leaving later calls their limit, a
  reasoning run that keeps going after its strategy runs out of output, the
  anchor binding, the whole-file edit, the longer repair output, the
  ES-module index, whole-file `NEED_FILES` replies and file requests that do
  not use up diff attempts. The budget test covers the 4-call reserve.
- `cargo fmt`, `cargo clippy` with `-D warnings` and the workspace tests pass
  in CI on Linux and Windows. On macOS, CI runs clippy for the CLI and the
  local runtime's tests. The release build passes.

## Still limited

- The laptop numbers come from one machine, one model and 20 exercises.
- A failing goal on that laptop still takes two to four minutes.
- A check that runs out of time ends the goal unverified instead of asking
  for a repair.
- Whether calibration keeps the thinking mode depends on the machine's
  speed, so the same model can run differently on two machines.

```text
npm install -g phonton-cli
```
