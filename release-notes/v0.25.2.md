# phonton-cli v0.25.2 — Claude 5.5 models work with an Anthropic key

With an Anthropic key, 0.25.1 could fail a goal with
`anthropic response missing content[0].text`. Claude Sonnet 5.5, Opus 5.5
and Haiku 5.5 think by default, so a reply can open with a `thinking` block
before the text, and Phonton read only the first block. Sonnet 5.5 and
Opus 5.5 are Phonton's default Anthropic models for its standard and
frontier tiers, so this hit goals whenever one of them chose to think.

## Every text block is read

Phonton now joins the `text` blocks of a reply and skips `thinking` blocks.
A reply with no text at all, for example one that spent its whole
`max_tokens` budget thinking, now fails with the API's `stop_reason` instead
of a missing-field error.

## Verified

- A regression test covers a reply that opens with a `thinking` block and a
  reply that has no text.
- Against the live API, `claude-sonnet-5-5` answered a short coding prompt
  with a `thinking` block followed by the text.
- On 0.25.1, an Aider Polyglot JavaScript exercise failed at a model call with
  this error. On 0.25.2 the same exercise got text back from every model call,
  and the Rust exercise `luhn-from` ended review-ready on Sonnet 5.5 with its
  tests passing.
- `cargo fmt`, `cargo clippy` with `-D warnings`, the workspace tests in CI,
  the release build, `phonton doctor`, and `phonton doctor --provider` against
  Anthropic all pass.

## Still limited

With a cloud key, Phonton verifies changes with cargo checks and tests and a
package's `npm test` script. For other stacks, Python included, a goal stops
with "Verification not run" instead of applying an unchecked change. Local
runs (`phonton goal --local`) take explicit `--check` commands.

## Install

```text
npm install -g phonton-cli
```

Or download a binary from GitHub Releases, or
`cargo install --git https://github.com/phonton-dev/phonton-cli phonton-cli --locked`.
