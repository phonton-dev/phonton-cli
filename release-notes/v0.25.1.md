# phonton-cli v0.25.1 — Local runs survive a busy laptop

0.25.0 recommends `qwen3.5:4b` for 4-6 GB GPUs, but on exactly that hardware
local goal runs often stopped halfway with `resource_pressure`. 0.25.1 lets a
model that is already loaded in VRAM keep working when the rest of the
machine is busy.

## A loaded model keeps working

`phonton goal --local` refused every model call once available host RAM fell
below 1.5 GiB, even when the exact calibrated model (same digest, same
context) was still loaded entirely in VRAM. That reserve covers starting the
runtime. A model that is already loaded holds its host memory, and the
available-RAM reading already excludes it, so the check counted that memory
twice. Running the project's checks between model calls, such as an offline
`npm ci` and jest, was enough to trip it with a browser and chat apps open.

A call to a copy held entirely in VRAM now needs 512 MiB of free host RAM.
On Ollama 0.34.2 with an RTX 4050, loading `qwen3.5:4b` at 16384 tokens took
about 700 MiB of host RAM; a later 7,000-token call to the loaded copy loaded
nothing. Everything else still fails closed:

- a cold load keeps the 1.5 GiB reserve (2 GiB when the model is partly
  offloaded to the CPU);
- a resident copy that is partly in RAM keeps the 1.5 GiB reserve;
- a loaded copy with another digest or a smaller context gets no exception
  and is admitted like a cold load;
- an unknown memory reading still stops the run before inference.

Residency is still checked again immediately before each call; it is an
observation, not a reservation.

In the 0.25.0 Aider Polyglot run on a 16 GB RAM, 6 GB RTX 4050 laptop, this
check ended 18 of 51 Phonton runs, including 13 of 17 JavaScript runs, about
100 seconds in, after the jest checks.

## Install

```text
npm install -g phonton-cli
```

Or download a binary from GitHub Releases, or
`cargo install --git https://github.com/phonton-dev/phonton-cli phonton-cli --locked`.
