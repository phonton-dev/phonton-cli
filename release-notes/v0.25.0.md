# phonton-cli v0.25.0 — Current local models, local first, comparable proof

Phonton is built for local coding models, but until this release it still
suggested 2024's `qwen2.5-coder` and fell back to Anthropic when no key was
set. 0.25.0 suggests the models people run today, starts local, measures
memory honestly, and ships a public benchmark runner so pass rates can be
compared with other harnesses on the same model.

## Models from 2026

`phonton models catalog` lists current local coding models and marks one for
this machine by its total memory (the largest GPU, or half of RAM when that is
larger):

| Memory | Suggested | Alternative |
| --- | --- | --- |
| under 6 GB | `qwen3.5:4b` | |
| 6-16 GB | `qwen3.5:9b` | `gemma4:12b` (10 GB and up) |
| 16-24 GB | `gpt-oss:20b` | |
| 24 GB and up | `qwen3.6:35b-a3b` | `qwen3.6:27b` |

The `qwen2.5-coder` entries are gone. Free memory no longer decides the
suggestion; the fit column still reports it.

## Local first

With no provider key anywhere, Phonton now defaults to a local model instead
of Anthropic. `phonton doctor` and `phonton models` name the
`phonton models setup MODEL` command for this machine first, then the provider
keys.

## Honest fit estimates

Fit estimates used to reserve 1 GiB per 4096 context tokens plus 25% of the
weights, so `qwen3.5:4b` could not be calibrated above 4096 tokens on a 6 GB
GPU that serves it at 16384. Estimates now read the KV cache size from the
installed model's attention metadata, add a fixed 1 GiB runtime reserve, and
accept a model that fits the largest GPU plus available RAM as partly
offloaded. On a 6 GB GPU, `qwen3.5:9b` is admitted once about 4 GiB of RAM is
free. A copy of the same model already loaded at another context no longer
hides its own memory from calibration or goal admission.

## Jest projects verify locally

Local goal runs can now verify jest projects with
`node node_modules/jest/bin/jest.js --ci --json`. Each check copy installs the
project's own jest with the reviewed offline `npm ci` (lockfile integrity, no
lifecycle scripts). A pass needs jest's JSON report to show at least one
passing test in candidate files, no failure, and V8 coverage of every edited
source. Unsupported jest flags, a missing `--json`, or skipped-only runs stay
Not run. Babel configuration is protected from model edits like
`jest.config.*`. A root `"test": "jest"` script proposes this check and its
preparation without `--check`.

Offline npm preparation now accepts lockfiles of up to 2,048 package entries
(was 512), within the existing 2 MiB bound, enough for a jest and babel
toolchain.

## Review shows what the model saw

`phonton review` and `phonton why-tokens` listed only the retrieved snippets,
often five unrelated ones at about 500 tokens, as the model's context. They now
list the files each prompt inlined whole or as excerpts, then the retrieved
snippets, with a per-prompt token estimate next to the provider-reported input
for every call.

## Help that doesn't download

`phonton models setup --help` took `--help` as a model name and started the
1.5 GB runtime download. `--help` after any `phonton models` command now
prints the usage.

## A benchmark anyone can rerun

`benchmarks/polyglot` runs an [Aider Polyglot](https://github.com/Aider-AI/polyglot-benchmark)
slice (Python, JavaScript and Rust) through three arms on the same local model
and prompt: Phonton, the bare model, and OpenCode. It reports pass rate,
**false-pass rate** (runs the arm called a success that fail the pristine
tests), tokens and wall time, and writes raw logs and diffs for every run.
`gpu_job.py` and `modal_job.py` run the slice on a rented or free GPU. Results
will be published separately once the runs finish.

## Install

```text
npm install -g phonton-cli
```

Or download a binary from GitHub Releases, or
`cargo install --git https://github.com/phonton-dev/phonton-cli phonton-cli --locked`.
